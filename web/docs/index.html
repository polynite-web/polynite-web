Advanced

Break through a brick wall

A physical chain, procedural bricks and an impact you can tune.

Open scene ↗
Try it step by step

Build a brick wall and swing a wrecking ball on a physical chain through it. Add scene controls for impact speed, masses, release angle and friction, with gentle, breach and demolition presets. Use procedural clay and reflective marble.

Connect your assistant to recreate it, then make it your own.

  1. Watch the ball make a breach through the wall, with each chain link simulated independently.
  2. Open Scene options (⋯), then Scene settings, and choose Doux, Percée or Démolition.
  3. Adjust impact speed, ball mass, brick mass, release angle or friction. Changes return the construction to its starting pose, paused.
  4. Use Replay to run the existing sequence with the new values, without recording.
  5. Save scene keeps your settings and the sequence for later.
  6. Ask your assistant to add different custom controls to another scene: each scene owns its own panel.
MCP example

This changes the impact settings of the opened scene and returns it to the start, paused. Use settings_replay to compare the result. These controls require an updated Polynite viewer.

Use polynite_scene with these arguments and a fresh action_id. Keep the current scene.

{
  "operation": "settings_set",
  "action_id": "replace-with-a-fresh-uuid",
  "values": {
    "impact_speed": 7,
    "ball_mass": 100
  }
}

MCP example

This snippet adds the illustrative command field only. The blue colour change is a separate action in the downloadable scene.

Use polynite_scene with operation: local, method: scene.cinematic, a new action_id, and this object as params.request. replace changes the whole timeline; keep existing steps when editing.

{
  "command": "replace",
  "seq": [
    {
      "op": "hold",
      "at": 0,
      "dur": 4
    },
    {
      "op": "text",
      "preset": "command-input-v2",
      "text": "Make it blue",
      "at": 0.4
    }
  ]
}

Get started

  1. Open Polynite in a desktop browser with WebGPU. Use procedural scene controls, or connect a compatible assistant using the MCP integration.
  2. Start small: create a few objects, inspect them and keep editing. Positions use metres; blocks of 0.25–0.4 m are a useful starting point.
  3. For conversational creation, ask in the connected assistant. Follow-ups target the same scene; a lost connection should be recovered before further edits.

Video signatures

Recording automatically adds a subtle opening cue and a short Polynite ending. The ending includes the logo, a progressive fade to 75% black, bloom only during the shine, and subtle entrance and closing sounds. Your creation prompt never needs to mention them.

On the updated engine, the signature is required at export even if preview controls or a saved scene remove it. Watermark remains a separate setting. Paid removal is not enabled yet. Compatible assistants can install the complete ending with scene.cinematic, request.command: set_branding and preset: polynite-ending-v4. Check the viewer capabilities first.

Cloud video links and retention

Download films you want to keep. Uploaded MCP videos have seven-day retention; signed read links expire within one hour and can be refreshed while the file remains available. Anyone with a signed link can view the video until expiry.

Two presets, short prompts

Show a command

command-input-v2 adds typed entry, quiet typing and Send cues, a luminous checkmark and a gentle exit. It is an illustrative overlay, not a live AI composer.

Start with: “Show a command field typing Make it blue, then validate it softly.”

Personalise the ending

polynite-ending-v4 keeps the signature, dimming, shine-only bloom and quiet cues together. Adjust its placement and sound volume without writing a long effects prompt.

The signature is automatic and required at export. You only need to name the preset when customising it.

Current limits

  • Rendering requires WebGPU and a ready viewer for scene edits.
  • Cloud uploads: 32 MiB/video, 16 videos/scene, 12 new uploads/account/day.
  • Recording accepts 30/60 FPS and 720/1080p. Encoder availability/formats depend on the browser.
  • MCP checkpoints retain data for seven days. Missing model files may need to be supplied again.
  • Long Firefox sessions have an unresolved memory-crash report. Firefox endurance and mobile/Safari recording are not certified.
  • Complex articulated scenes require verification. Command acceptance does not prove a correct visible result.

See troubleshooting.

Models, providers and access

Importing and inspecting a local model is separate from sharing or using an AI service. Sharing, checkpoints and cloud video delivery can upload data; connected generation providers may require an account and charge for usage. See data handling.

Jev connections inside the app, Polynite credits and local AI are foundations in development, not public features of the current MCP integration. The plugin has not yet been approved for the public OpenAI directory.
