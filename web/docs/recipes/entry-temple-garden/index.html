01 / COMPOSE

How the recipe works

  1. Export a real opening as a typed entry port. Its position, direction and dimensions follow the wall.
  2. Preview compatible ports, then estimate the complete connection before applying it.
  3. Align the thresholds with opposing directions; keep roofs, materials, framing and stairs in recipes.

The engine supplies operators. The recipe chooses their arrangement, materials and behaviour. Change the composition to invent a different structure.

02 / ASK

Start a conversation

In Polynite, discover architecture connections and the anchor/wall operators. Use an editable assembly recipe: export entrance from the hall wall opening and declare a root entry anchor on the gallery. Inspect both IDs, preview architecture.connections for gallery/from with target hall, then estimate and apply attach:{to:hall,anchor:entrance,from:back000000}. Keep the roof context link and recipes independent. Use compatible doorway dimensions, shared procedural materials and instances. Move/rotate/resize the provider and verify that the thresholds stay aligned and the walls leave a real passage. Preserve overrides; save and reopen the complete scene. Enable soft floor reflections in scene settings.

Example and versioned recipe: https://explore.polynite.io/docs/recipes/entry-temple-garden/

Paste into your connected assistant. A prompt invites a new interpretation; the scene and JSON preserve this exact reference.

03 / VERIFY

An example you can test.

These expectations are also consumed by the regression runner. Check geometry and behaviour, then look at the result.

  • roof_link · gallery · observed at 0 / 3 / 6 seconds
  • port_link · gallery · observed at 0 / 3 / 6 seconds

Explicit directed ports, not global welding. Entry targets must come from real wall opening exports. The consumer connector is a root typed anchor with input-only pose and dimensions; no nested, context-dependent or repeated from port. Entry/wall fit compares width and height; floor/support fit compares width and depth. The target is not enlarged automatically. Preview checks interfaces and cycles; estimate also checks geometry, roof contact and overrides. Detach before moving a constrained consumer. No automatic obstacle routing or arbitrary mesh Boolean.

For assistants & developers

Requires commands.recipe_program, commands.recipe_assemblies, commands.recipe_instances, commands.recipe_junctions, commands.recipe_roof_ports, commands.recipe_context, commands.surface_prisms, commands.recipe_connections from the connected engine. Discover operators before composing, estimate before applying, and preserve user edits.

Minimal native edit after opening the example; stop playback before editing:

{
  "actions": [
    {
      "op": "architecture",
      "id": "hall",
      "params": {
        "rise": 1.5
      }
    }
  ]
}

Send via scene.apply. The value shown is the recipe default; change it within the input bounds in the JSON. Remote MCP clients should discover their current tool schemas instead of assuming this native envelope.
