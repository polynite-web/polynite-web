THE COMMON TOOLKIT

Learn a tool. Combine an idea.

Each operator does one reusable job. Read these small examples, then discover the full contract on your connected engine.

Shape a surface surface

Create a curved petal, leaf, panel or roof from a shared profile. Shape belongs to parameters, not a species name.

{
  "id": "pet",
  "op": "surface",
  "role": "petal",
  "s": [
    0.2,
    0.4,
    0.05
  ],
  "surface": {
    "cup": 0.4
  }
}
Start with a solid primitive

Compose cubes, spheres, cylinders, cones or planes; assign a reusable material role.

{
  "id": "post",
  "op": "primitive",
  "kind": "cube",
  "s": [
    0.1,
    1,
    0.1
  ]
}
Connect two points beam

Build a support between explicit endpoints. A recipe can compute each endpoint from its surroundings.

{
  "id": "leg",
  "op": "beam",
  "a": [
    0,
    0,
    0
  ],
  "b": [
    0,
    1,
    0
  ],
  "width": 0.05
}
Name a connection anchor

Expose a stable point for another assembly to attach to or reference.

{
  "id": "tip",
  "op": "anchor",
  "p": [
    0,
    1,
    0
  ]
}
Arrange many parts repeat

Repeat a node with stable indices. Use @i and @j in expressions to choose each piece's placement.

{
  "count": 8,
  "rows": 1
}
Articulate a part motion

Animate a part around an axis without rebuilding its topology every frame.

{
  "enabled": 1,
  "axis": [
    1,
    0,
    0
  ],
  "from": 18,
  "to": 108,
  "period": 4
}
Calculate a relationship expression

Combine bounded numeric expressions and parameters. For example, double a length or arrange pieces around a circle.

[
  "mul",
  "$width",
  0.5
]
Declare the surroundings context

Reference a named support, path or assembly anchor. Relationships are explicit and local.

[
  {
    "name": "base",
    "object": "terrain",
    "point": "top"
  }
]
Reuse a calculation let

Give a bounded expression a name, then reference it as %half. This keeps a recipe readable.

[
  {
    "name": "half",
    "value": [
      "mul",
      "$width",
      0.5
    ]
  }
]
Sample the surroundings spatial

Sample height on a declared cube support, or signed distance from a support footprint or path corridor. Arbitrary mesh terrain is not covered.

[
  "height",
  "@base",
  0,
  0
]
Leave room when

Conditionally emit a piece. Zero skips it; one keeps it. Include a piece's whole footprint when reserving clearance.

[
  "gte",
  [
    "distance",
    "@walk",
    0,
    0
  ],
  0.3
]
Define a shared shape prototype

Name a primitive or parameterized surface once in program.prototypes. Reuse existing geometry operators; keep style in the recipe.

{
  "id": "rib",
  "op": "surface",
  "surface": {
    "kind": 2,
    "profile": [
      [
        0,
        0.06
      ],
      [
        1,
        0.04
      ]
    ],
    "path": [
      [
        -0.5,
        0,
        0
      ],
      [
        0,
        1,
        0
      ],
      [
        0.5,
        0,
        0
      ]
    ]
  }
}
Repeat without copying the mesh instance

Place a prototype with independent transforms, material role and rigid motion. Compatible copies share GPU geometry; the scene includes its definitions.

{
  "id": "arch",
  "op": "instance",
  "source": "rib",
  "repeat": {
    "count": 8
  },
  "p": [
    0,
    0,
    "@i"
  ],
  "s": [
    3,
    3,
    3
  ]
}
Draw the silhouette profile

Supply 2–16 ordered width points for a ribbon, lathe or tube. Expose the widths as recipe inputs.

[
  [
    0,
    1
  ],
  [
    0.2,
    0.6
  ],
  [
    0.8,
    0.6
  ],
  [
    1,
    1
  ]
]
Follow your own path sweep

Sweep a ribbon or tube along 2–16 XYZ points. Reuse it for arches, stems and structural ribs; shapes are cached at edit time.

{
  "kind": 2,
  "path": [
    [
      0,
      0,
      0
    ],
    [
      0.2,
      0.5,
      0
    ],
    [
      0.5,
      1,
      0
    ]
  ],
  "profile": [
    [
      0,
      0.1
    ],
    [
      1,
      0.04
    ]
  ]
}
Compose reusable groups assembly

Define a bracket, frontage or storey once, then compose and repeat it. The recipe chooses the structure; the local engine validates the graph and shares compatible geometry. Uniform scale and yaw keep transforms free of shear.

{
  "assemblies": [
    {
      "id": "pair",
      "nodes": [
        {
          "id": "col",
          "op": "instance",
          "source": "column",
          "repeat": {
            "count": 2
          },
          "p": [
            "@i",
            0,
            0
          ]
        }
      ]
    }
  ],
  "nodes": [
    {
      "id": "row",
      "op": "assembly",
      "source": "pair",
      "repeat": {
        "count": 4
      },
      "p": [
        0,
        0,
        [
          "mul",
          2,
          "@i"
        ]
      ]
    }
  ]
}
Your first editable recipe: a row of posts

Start with a primitive, repeat it, and expose count, spacing and height. This same composition can become fence posts, columns or stems. Add beams, surfaces or context as needed.

{
  "id": "study",
  "module": "assembly",
  "seed": 17,
  "program": {
    "version": 1,
    "inputs": [
      {
        "name": "count",
        "min": 1,
        "max": 12,
        "value": 6,
        "integer": true,
        "group": "shape"
      },
      {
        "name": "spacing",
        "min": 0.2,
        "max": 1,
        "value": 0.4,
        "group": "shape"
      },
      {
        "name": "height",
        "min": 0.2,
        "max": 3,
        "value": 1,
        "group": "shape"
      }
    ],
    "nodes": [
      {
        "id": "post",
        "op": "primitive",
        "kind": "cube",
        "repeat": {
          "count": "$count"
        },
        "p": [
          [
            "mul",
            "@i",
            "$spacing"
          ],
          [
            "mul",
            "$height",
            0.5
          ],
          0
        ],
        "s": [
          0.1,
          "$height",
          0.1
        ]
      }
    ]
  }
}

This is a recipe object. Estimate it before sending it with an architecture action. Its ID is a placeholder: choose an unused stable ID in the current scene.
