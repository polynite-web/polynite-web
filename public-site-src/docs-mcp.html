Big effects. Small prompts.

Try: “Create a colourful block explosion with a dramatic cinematic style.” Polynite handles the closing identity automatically when recording. You do not need to request a logo, sound or fade.

A cinematic title gives gentle movement and fades. A dramatic title approaches the camera more strongly, with a visible transparency fade and position-driven stroke erasure. Open the example to inspect or edit the result.

Presets for connected assistants

Check scene.cinematic status.branding.preset_supported. A text clip can use preset: "dramatic-title-v1" or "cinematic-title-v1", plus text and optional overrides. Resolved settings are saved in the scene; reopening preserves them. Unknown presets are rejected.

{"op":"text","text":"EXPLODE","preset":"dramatic-title-v1"}

The implicit export preset polynite-ending-v3 includes a 1.1-second logo, a progressive fade to 75% black starting 0.35 seconds beforehand, subtle audio and a background bloom synchronized with the logo light. Export restores the managed ending even if a scene removes it. Paid removal is not enabled yet; it will require an account entitlement, never an instruction from an assistant. Interactive tutorial exploration hides the ending. The v3 ending preset automatically extends an existing final orbit through the complete ending, preserving the content duration and keeping motion alive at the cut. It adds no orbit to a stationary film. Check status.branding.outro_orbit_continuation_supported.

Camera moves that flow

Camera movement eases automatically. Consecutive moves on the same axis share their speed at the join; changes of axis ease gently through rest. No extra wording is needed in your prompt.

Camera settings for assistants

Check status.branding.camera_smooth_transitions_supported. Orbit, dolly and rise use smooth transitions by default. transition: smooth makes the default explicit; transition: cut retains separate legacy easing. The updated dramatic-title-v3 keeps the title closer to a readable facing, with a gentler tilt and rotation. Explicit fields still override the preset.

Build tension, then release

The dramatic explosion starts close to the structure and slowly pulls back while the title approaches the camera. The blocks launch when 75% of the title strokes have crossed the disappearance boundary, followed by a small additional camera retreat. In the updated template, orbiting starts after this retreat, while the simulation is paused. The prompt stays the same.

Synchronisation for assistants

Check status.branding.text_exit_sync_supported. Give a spatial text clip a unique id. A freeze with preset: dramatic-reveal-v1 and release_text uses a default threshold of 0.75. A dolly with preset: dramatic-pullback-v1 and the same reference backs off by 22% until that crossing. Explicit release_fraction overrides the threshold. Polynite resolves the duration from the actual glyph layout and motion when authoring or reopening; changing the title's motion recalculates it. Missing, ambiguous and unreachable references are rejected. Transparent opacity fades are separate from this stroke measurement.

[{"op":"freeze","preset":"dramatic-reveal-v1","release_text":"title"},{"op":"dolly","preset":"dramatic-pullback-v1","release_text":"title"},{"op":"text","id":"title","text":"EXPLODE","preset":"dramatic-title-v2","at":0}]

A title you can read

The dramatic title starts closer to the blocks, with a flatter line facing the viewer. The complete word has a brief readable moment before its position-driven exit. Your prompt stays unchanged.

Text curvature for assistants

Check status.branding.text_curvature_supported. Use preset: dramatic-title-v5 for these defaults. The advanced curvature control ranges from 0 (a straight tangent line) to 1 (a circular ring, the existing default). The preset also keeps letters facing the camera for readability. Advanced camera_facing: 0..1 controls this independently of text movement. Check status.branding.text_camera_facing_supported. Spatial release timing uses the same glyph geometry as the rendered text. Explicit fields override the preset.

For a smooth retreat at the explosion, place a dolly clip with preset: dramatic-impact-v1 at the release time, directly after the anticipation dolly. The engine joins their speeds automatically.

A shared burst, a closer view

A curved title can start on a ring and be blown outward with the scene, without assigning letters to new circular positions. A short bass-and-air cue and a small screen shake add impact. These optional controls require an updated viewer.

Small presets for assistants

Use shockwave-title-v1 for radial letters. At the release time, add explosion-sound-v1 on a sound clip and explosion-shake-v1 on a camera_shake clip. The shake is a short, bounded projection offset; it never changes the saved camera pose. Check the corresponding capabilities first.

For screen captions such as BUILD SOMETHING, typewriter-flow-v1 starts the exit halfway through the entrance. The two stroke timelines overlap; later letters continue appearing while earlier letters disappear. exit_at controls the local exit start, with -1 preserving older scenes. The closing preset boosts background bloom only during the final logo shine. To keep a scene label present after recording, use keep_after_video: true, hide_at: -1, fade_out: 0.

Make the title burst

Try a text explosion: scatter the whole letters or break them into smaller fragments. These optional effects leave the published tutorial unchanged and require an updated viewer.

Text effects for assistants

Check status.branding.text_shatter_supported. Use shatter-title-v1 for fragments, or scatter-title-v2 for whole letters that drift towards the screen edges, with gentle card rotation and a typewriter/transparency exit. For an expanding ring with separate letters turning around their local horizontal X axis, use ring-explode-title-v1 after checking status.branding.text_ring_explosion_supported. These are presets for ring text. For example:

{"op":"text","text":"EXPLODE","preset":"shatter-title-v1"}

shatter_at is the burst time in local clip seconds; defaults to 0.95. shatter_strength ranges from 0 to 5; shatter_grid is an integer from 1 to 4. shatter_style: outward selects a coherent screen-aligned path instead of the older random burst. shatter_style: ring expands the letters radially; shatter_spin: 0..4 controls local-X turns per second. The ring preset keeps typewriter and transparency fades. The grid automatically becomes coarser on long text to fit the per-title fragment budget. Fragments are a replayable visual effect, without physical collisions. Screen captions and image signatures do not support this effect.

Text that moves naturally

For a moving 3D title, choose a position-driven exit: letters erase their strokes as they cross the disappearance boundary. If the text stops, the erasure stops too. A separate transparency fade can soften the result.

Start and end ring radius control a gentle approach towards the camera. The exit position, direction and crossing band are editable in the Cinematic text controls and through MCP. Ask your assistant to check whether your connected viewer supports these controls first.

Advanced MCP text clip
{"op":"text","text":"EXPLODE","mode":"ring","dur":2,"in":0.72,"exit":"spatial_type","exit_position":65,"exit_direction":"left","exit_softness":0.8,"radius":1.2,"radius_to":2.7,"turns":0.26,"opacity_in":0.5,"opacity_out":0.4}

Use scene.cinematic via the local operation after checking status.branding.text_spatial_exit_supported. Exit position is in degrees relative to the initial facing; the crossing band is in em. Radius is relative to the scene subject, and radius_to:0 keeps it unchanged. The out duration does not drive spatial erasure. Closing signature clips accept branding_fade_duration in seconds independently of branding_fade_lead and their own duration.

Exact fields, small operations

Read polynite_operation_help for a schema/minimal example, even without a live scene. Check capabilities for runtime support.

{"operation":"record_video","action_id":"fresh-unique-id","duration":5}

Defaults: landscape, 1080p, 60 FPS, start from zero, restore the scene and hide text afterwards. Query video_status, then video_links. Do not record again while the first operation runs.

Choose how blocks collide

Rounded contacts are the default, so blocks tumble more naturally around their bevelled edges. For a large construction, ask your assistant to use simpler box collisions, or keep rounded contacts on selected objects. This changes the physical shape; the visible blocks stay the same.

Auto

Match the visible primitive. The default keeps bevelled blocks rounded and spheres spherical.

Box

A simple box with 8 vertices and 6 faces. Less work for the physics solver, with less accurate contact around curved corners.

Rounded

Keep bevel contacts for blocks you want to inspect closely. The current collider uses 44 vertices; the engine reports its actual face count.

“Create a large pile with box collisions, but use rounded collisions for the three blocks in the foreground.”

Collision profiles require an updated viewer. Existing bodies must be paused before their profile changes. Profiles never switch automatically because the scene gets busy.

Collision settings for MCP

Check capabilities.commands.physics_collision_shape. Set physics.collision_shape to auto, box or rounded as the default for new cube bodies. A body's collision_shape overrides that default. A sphere body accepts only auto; the scene's cube profile does not affect spheres. Preserve the scene default during physics_upsert. Read physics_status for each body's resolved collision_shape, collision_vertices and collision_faces. Arbitrary face counts and custom collision meshes are not supported by these profiles.

Understand the result

  • observed: a read returned information.
  • accepted: command accepted; visual inspection is separate.
  • in_progress: recording/transfer underway; query status.
  • completed: completion reported; check file availability/rendering.
  • rejected: correct the request using the error.
  • unknown: inspect this scene before another mutation. Never blindly replay.

Other models and provider keys

Compatible tool-calling models use the same command contract; support still depends on the client and viewer capabilities. A typed-decision adapter can choose an operation while application code validates arguments and authorization.

Jev through Vercel AI Gateway has been exercised on eight routing examples. That does not certify every action or make Jev available inside the app. User-key connections are currently disabled; ChatGPT and Claude do not receive a user's provider key.

Verify, then continue

Read scene state after a change, and inspect the actual view when appearance matters. Captures require a rendering viewer and a compatible host response. Current host-capture and long-recording issues remain under investigation; a successful command alone is not visual proof.
